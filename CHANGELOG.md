# Changelog

All notable changes to Cortex are documented here. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow SemVer once code exists.

## [Unreleased]

### Fixed
- 2026-11-28 — The containerised API now gets the broker address on the compose network (it would have tried to enqueue jobs to itself) [TASK-05.06].
- 2026-11-27 — The local-storage symlink-escape test had silently become a skip on Linux CI after storage folders became lazy; it runs again, and may now skip only on Windows [TASK-04.05 follow-up].
- 2026-11-27 — Local storage no longer creates folders when the app starts (it would fail on a read-only container filesystem); folders are created on the first upload [TASK-04.05].
- 2026-11-27 — Local storage: temporary files now live in `<root>/.tmp/`, so real document paths stay under Windows' 260-character limit [TASK-04.04].

### Added
- 2026-11-28 — Word (.docx) text extraction: headings become section paths, tables become readable rows, tracked deletions and field codes are left out; memory stays flat for long documents and zip bombs are stopped by counting the bytes actually unpacked (`DOCX_INVALID`, `ARCHIVE_TOO_LARGE`, `EXTRACTION_EMPTY`) [TASK-06.02].
- 2026-11-28 — PDF text extraction: text per page with page numbers, PDFs that only restrict printing/copying open normally, password-protected PDFs and scans without text are refused with clear codes (`PDF_ENCRYPTED`, `EXTRACTION_EMPTY`, `PDF_INVALID`); not yet connected to the processing job (TASK-06.06) [TASK-06.01].
- 2026-11-28 — Background worker and scheduler as opt-in Docker services (`scripts\dev.cmd workers up | down | logs`): never started by default, memory-limited (about 190 MiB together in use), hardened like the API, with a graceful shutdown that requeues unfinished work [TASK-05.06].
- 2026-11-28 — Reprocess and delete documents: any member can reprocess a document (refused while it is being processed); the uploader or an admin can delete it, which hides it at once and removes its file and records in the background, safely repeatable; deleting a knowledge base now deletes its documents the same way and finally removes the knowledge base itself [TASK-05.05].
- 2026-11-28 — Background jobs are started reliably: an upload enqueues its job only after it is saved (and still succeeds if the broker is down); a scheduled reconciler re-enqueues jobs whose message was lost and takes back jobs whose worker died, retrying or failing them; until document processing exists (Phase 6) documents fail plainly with `PROCESSING_NOT_AVAILABLE` [TASK-05.04].
- 2026-11-28 — Retry handling for background jobs: temporary failures are retried after a randomized, growing delay while attempts remain; permanent failures (e.g. an encrypted PDF) fail at once with a clear code; unexpected errors are retried, logged once with their traceback, and never stored with their text; a job taken back mid-work stops without writing anything [TASK-05.03].
- 2026-11-27 — Processing-job lifecycle: a job can be claimed by exactly one worker (one atomic database update), the claim carries a fencing token so a stalled worker can never overwrite the result of the worker that took over, leases are renewed by a heartbeat, failures are retried or made final in the same update, and the document's status moves with its ingest job [TASK-05.02].
- 2026-11-27 — Background worker foundation: a Celery app with at-least-once delivery (late acknowledgement, requeue if a worker dies), JSON-only messages, time limits, one event loop and database pool per worker process, JSON logs with the task id, and a `cortex.ping` health task; verified booting in the hardened container [TASK-05.01].
- 2026-11-27 — Document reads: list per knowledge base (newest first, status filter, case-insensitive filename search), document detail with its latest job, a lightweight status poll, and download (S3: short-lived presigned link; local: streamed attachment with `nosniff`); documents being deleted or in a deleted knowledge base are invisible everywhere [TASK-04.06].
- 2026-11-27 — Upload endpoint `POST /orgs/{org_id}/knowledge-bases/{kb_id}/documents`: any member uploads a PDF, Word or text file; it is stored and recorded as a `PENDING` document with a `QUEUED` processing job in one transaction, answered with 202; an unknown knowledge base is refused before the file is read; 30 uploads per user per hour [TASK-04.05].
- 2026-11-27 — Document intake service: the same file is stored only once per knowledge base (409 `DOCUMENT_DUPLICATE` with the existing document's id, checked before anything is written); two identical uploads at the same moment produce exactly one document; a failed, raced or cancelled upload never leaves a file behind; a knowledge base cannot be deleted halfway through an insert [TASK-04.04].
- 2026-11-27 — Upload intake: files are received as a stream with the size limit enforced while they arrive (oversized uploads are refused without being read), the real type is detected from the bytes (PDF, Word .docx, UTF-8 text and Markdown; macro-enabled, encrypted and zip-bomb archives refused), and display filenames are sanitized; new error codes `INVALID_UPLOAD`, `FILE_TOO_LARGE`, `UNSUPPORTED_FILE_TYPE` (with a reason), `FILE_EMPTY` [TASK-04.03].
- 2026-11-27 — Knowledge bases API: create (ADMIN), list and get with document statistics (members), partial update with a notice when chunking changes, soft delete (202) that frees the name at once; names unique per organization ignoring case, also under concurrent requests; every route covered by the tenant-isolation framework [TASK-04.02].
- 2026-11-27 — File storage layer: one `StorageBackend` contract with a local-filesystem backend (confined to its root by two independent checks, atomic writes) and an S3 backend (server-side encryption on every object, private objects, presigned downloads forced to `attachment`); uploads are hashed and size-limited in a single streaming pass and never leave partial objects; S3 outages map to 503 `STORAGE_UNAVAILABLE`. New settings `CORTEX_STORAGE__S3_SSE`, `__S3_KMS_KEY_ID`, `__PRESIGNED_URL_TTL_SECONDS` [TASK-04.01].
- 2026-11-27 — Security model document (`docs/architecture/security-model.md`): assets, trust boundaries, STRIDE threat table, authentication and session lifecycle, tenancy, roles, rate limits, logging and secrets, and the known gaps with the task that closes each [TASK-03.09].
- 2026-11-27 — Tenant-isolation test framework: every API route must be classified; each organization-scoped route is probed from another organization (owner, admin and member) and must answer exactly like a non-existent organization while changing nothing in the database; a new route without a case fails the build [TASK-03.08].
- 2026-11-27 — Rate limiting on login (10/min per IP, 5/min per account) and registration (5/hour per IP): Redis sliding window checked atomically, 429 with `Retry-After`, fails closed (503) if Redis is down, no raw IPs or emails stored or logged; `CORTEX_RATE_LIMIT__*` settings, and staging/production refuse to start with limiting disabled [TASK-03.07].
- 2026-11-27 — Organization and member management API: list/create/get/rename organizations; list/add/re-role/remove members with owner/admin rules; an organization can never lose its last owner, even under concurrent changes [TASK-03.06].
- 2026-11-27 — Organization context for `/orgs/{org_id}/…` routes: membership verified per request (non-members and unknown orgs get an identical 404), `require_role` / `AdminContext` / `OwnerContext` (403), role changes effective immediately, user and org ids in request logs [TASK-03.05].
- 2026-11-27 — Auth API: register (user + organization + OWNER, atomic and race-safe), login (enumeration-resistant), refresh (CSRF header + rotation), logout, `GET/PATCH /auth/me`, change password (ends other sessions); `CurrentUser` dependency with Swagger "Authorize" support [TASK-03.04].
- 2026-11-27 — Refresh-token sessions: opaque 256-bit tokens stored as SHA-256, rotation on every use, strict reuse detection that revokes the whole session family, logout and "sign out everywhere", hardened refresh cookie [TASK-03.03].
- 2026-11-26 — JWT access tokens: HS256 pinned, all claims required (`typ`, `iss`, `aud`, `jti` …), dedicated derived key, user id only, `TOKEN_EXPIRED` vs `INVALID_TOKEN` (401) [TASK-03.02].
- 2026-11-26 — Password hashing with Argon2id (OWASP parameters, transparent rehash on login, NFKC normalisation, constant-time dummy verify, off-event-loop async API) and a NIST-style password policy [TASK-03.01].
- 2026-11-26 — Test harness: random test order on every run (pytest-randomly), integration tests auto-marked by folder, persisted factories, an `api_client` on the migrated scratch database, faster isolation (integration suite ~43 s → ~28 s), and docs/testing/README.md [TASK-02.08].
- 2026-11-26 — Keyset pagination for list endpoints: `{items, next_cursor, has_more}`, signed cursors bound to one listing, stable under concurrent inserts/deletes, 400 `INVALID_CURSOR` for any bad cursor [TASK-02.07].
- 2026-11-26 — Consistent error responses: domain exceptions mapped centrally to `{"error": {code, message, details, request_id}}` for every non-2xx (including 404/405/422/500); 422 no longer echoes submitted values; unexpected errors return a generic 500 and are logged once with the request id [TASK-02.06].
- 2026-11-26 — Chat and usage schema: conversations (KB tenant FK; ownership requires organization membership), messages (role/status CHECKs, token/latency metrics, retrieval trace), citations (snapshot that survives document deletion), usage events (exact numeric(12,6) costs that survive deletions) [TASK-02.05].
- 2026-11-26 — Document schema: knowledge bases (soft delete, per-org case-insensitive names, chunking CHECKs), documents (per-KB de-duplication via partial unique index), chunks (deterministic ids, range CHECKs), processing jobs (one active job per document). Composite foreign keys make cross-tenant and cross-KB rows impossible at the database level [TASK-02.04].
- 2026-11-26 — Identity schema: users (case-insensitive unique email), organizations, organization memberships (OWNER/ADMIN/MEMBER with a database CHECK), refresh tokens (hashed, rotation family, self-reference); first migration; relationships require explicit loading [TASK-02.03].
- 2026-11-26 — Alembic migrations: async env with the settings-driven URL, naming-convention constraint names, ruff post-write hook, `dev migrate` / `dev revision`, migrations shipped in the image, and migration safety tests (round trip, stairway, model drift, single head) [TASK-02.02].
- 2026-11-26 — Database foundation: async SQLAlchemy engine + session-per-request dependency, declarative Base with constraint naming convention, UUIDv7 primary-key and server-timestamp mixins, pool disposal on shutdown [TASK-02.01].
- 2026-11-26 — GitHub Actions CI: lint, format, strict mypy, full tests with PostgreSQL/Redis/Qdrant service containers, Docker image build + hardened smoke test; actions pinned to commit SHAs [TASK-01.09].
- 2026-11-26 — `scripts/dev.cmd` / `scripts/dev.ps1` developer commands: up (-App), down, ps, logs, api, test (pytest args pass through), lint, format, check, reset (typed confirmation) [TASK-01.08].
- 2026-11-26 — Structured JSON logging for every logger (structlog + stdlib), `X-Request-ID` propagation, access log without query strings, recursive secret redaction, `CORTEX_LOG_FORMAT` [TASK-01.07].
- 2026-11-26 — Backend container image: two-stage uv build, non-root, read-only root FS, all capabilities dropped, liveness health check; `api` compose service behind the opt-in `app` profile on 127.0.0.1:18000 [TASK-01.05].
- 2026-11-26 — FastAPI app factory with `/api/v1/health/live` and `/api/v1/health/ready` (concurrent, time-bounded checks of PostgreSQL, Redis, Qdrant; 503 when any is down) [TASK-01.06].
- 2026-11-26 — Local infrastructure: Docker Compose with PostgreSQL 17.12, Redis 7.4.12, Qdrant 1.20.2 (non-root), health checks, named volumes, localhost-only ports 15432/16379/16333/16334 [TASK-01.04].
- 2026-11-26 — Typed settings (`app.config`): `CORTEX_*` env vars with nested groups, `.env.example`, staging/production refuse unsafe defaults, unknown variables rejected, secrets masked [TASK-01.03].
- 2026-11-26 — Backend scaffold: uv project pinned to Python 3.12, `app` package tree per ARCHITECTURE.md, ruff + strict mypy + pytest configuration, project-layout tests [TASK-01.02].
- 2026-11-26 — Repository hygiene: `.gitignore`, `.gitattributes`, `.editorconfig` [TASK-01.01].
- 2026-11-26 — Project planning documents: PROJECT_PLAN, TASK_TRACKER, ARCHITECTURE, DATABASE_DESIGN, API_SPECIFICATION, TECH_STACK, DEVELOPMENT_GUIDELINES, DECISIONS, CHANGELOG, SESSION_LOG, README, and the `docs/` structure.
